EXPLICATION DU DIAGRAMME
════════════════════════════════════════════════════════════════════════════════

1. COUCHE CRDT CORE (Bleu)
   ────────────────────────────────────────────────────────────────────────
   CRDTIdentifier
   ├─ Représente chaque changement de manière unique
   ├─ Triple (timestamp, nodeId, disambiguator)
   └─ Garantit ordre total via compareTo()

   CRDTElement
   ├─ Enveloppe un caractère avec ses métadonnées
   ├─ Stocke deletion flag (soft delete)
   └─ Comparable par son identifiant

   CRDTOperation
   ├─ Représente une opération atomique (INSERT/DELETE)
   ├─ Immutable → Serializable
   └─ Enregistre leftId/rightId pour positionnement

   CRDTDocument
   ├─ Stockage principal : SortedMap<CRDTIdentifier, CRDTElement>
   ├─ O(log n) insertion/suppression
   ├─ Horloge logique pour causalité
   └─ Historique des opérations (undo/redo)

   CRDTEngine
   ├─ Orchestrateur multi-documents
   ├─ Queue des opérations en attente
   ├─ Listeners pour notifications
   └─ applyRemoteOperation() = cœur de la convergence


2. COUCHE COLLABORATION (Vert)
   ────────────────────────────────────────────────────────────────────────
   CollaborationEngine
   ├─ Intègre CRDTEngine pour synchronisation
   ├─ Coordonne PermissionManager, WebRTC, Presence
   └─ Synchronise les changements entre réplicas

   PermissionManager
   ├─ Contrôle d'accès par utilisateur
   ├─ Gère granularité des permissions (lecture/écriture)
   └─ Vérifie autorisation avant opération

   WebRTCCallManager
   ├─ Établit connexions P2P WebRTC
   ├─ Gère ICE candidates
   ├─ Heartbeat pour détection déconnexion
   └─ Reconnexion avec exponential backoff

   ClientPresenceManager
   ├─ Suivi des utilisateurs actifs
   ├─ Synchronisation des curseurs en temps réel
   ├─ États utilisateur : editing, offline, etc.
   └─ Notifications d'arrivée/départ


3. COUCHE LSP BRIDGE (Jaune)
   ────────────────────────────────────────────────────────────────────────
   DocumentReplicaStore
   ├─ Wraps CRDTEngine pour chaque document
   ├─ Convertit SyncMessage → CRDTOperation
   └─ Applique opérations distantes via CRDT

   LspBridgeSession
   ├─ Session LSP par utilisateur
   ├─ HandlerdidChange → DocumentReplicaStore
   └─ Publie diagnostics/hover info via LSP protocol

   SyncServerAdapter
   ├─ Lance processus LSP externe
   ├─ Relie processus LSP avec bridge
   ├─ Gère stdin/stdout du serveur LSP
   └─ Forwarder messages bidirectionnels

   LspProcessManager
   ├─ Lifecycle du processus LSP
   ├─ Capture erreurs/sortie standard
   └─ Graceful shutdown + force kill


4. COUCHE SIGNALING & NETWORKING (Cyan)
   ────────────────────────────────────────────────────────────────────────
   SignalingWebSocketServer
   ├─ Serveur WebSocket central
   ├─ Gère connexions des clients
   ├─ Route messages de signaling
   └─ Broadcast/unicast

   RoomManager
   ├─ Gère création/suppression de rooms
   ├─ Ajoute/retire utilisateurs
   └─ Maintient limite de capacity

   Room
   ├─ Représente session collaborative
   ├─ Liste des utilisateurs membres
   ├─ File d'attente des messages
   └─ Broadcast interne

   UserSession
   ├─ Représente session utilisateur unique
   ├─ timestamp pour détection inactivité
   └─ Async cleanup après disconnection


5. COUCHE APPLICATION (Gris)
   ────────────────────────────────────────────────────────────────────────
   DistributedIDEApp
   ├─ Classe main, extends Application (JavaFX)
   ├─ Initialise tous les services
   ├─ Lance scène principale
   └─ Gère lifecycle application

   WorkspaceManager
   ├─ Gère dossier workspace
   ├─ Liste des projects
   ├─ Projet actuellement ouvert
   └─ Coordination FileService, GitService

   FileService
   ├─ I/O disque abstrait
   ├─ Cache des fichiers ouverts
   ├─ Scanning recursive du workspace
   └─ Détection changements externals


6. SUPPORT SERVICES (Gris)
   ────────────────────────────────────────────────────────────────────────
   ProjectExecutionManager
   ├─ Exécuteurs par langage (Java, Python, etc.)
   ├─ Gère processus execution
   ├─ Capture stdout/stderr
   └─ Nettoyage après termination

   GitService
   ├─ Abstraction JGit
   ├─ Commit/Push/Pull
   ├─ Branch management
   └─ Merge avec CRDT sync

   LocalTerminalService
   ├─ Processus système local
   ├─ Ligne de commande arbitraire
   ├─ Buffer sortie
   └─ Signal handling

   GlobalExceptionHandler
   ├─ Capture exception globale
   ├─ Logging centralisé
   ├─ Dialog utilisateur
   └─ Graceful degradation

FLUX DE DONNÉES PRINCIPAL
════════════════════════════════════════════════════════════════════════════════

1. ÉDITION LOCALE:
   User types → DistributedIDEApp → WorkspaceManager → FileService
   ↓
   → CollaborationEngine → CRDTEngine.insert()
   ↓
   → CRDTDocument (SortedMap)
   ↓
   → pendingOperations (queue)

2. SYNCHRONISATION:
   pendingOperations → SignalingServer (WebSocket)
   ↓
   → Network → RoomManager.broadcast()
   ↓
   → UserSession (autres réplicas)

3. APPLICATION DISTANTE:
   Remote CRDTOperation → CRDTEngine.applyRemoteOperation()
   ↓
   → Idempotente + Commutative
   ↓
   → SortedMap (ordre automatique)
   ↓
   → LSP Bridge (si change LSP)
   ↓
   → LspBridgeSession → DocumentReplicaStore
   ↓
   → Diagnostics/Suggestions

4. SUPPORT LSP:
   File change → LspBridgeSession.handleDidChange()
   ↓
   → DocumentReplicaStore.toRemoteOps()
   ↓
   → Remote LSP Server (process)
   ↓
   → LspProcessManager → SyncServerAdapter
   ↓
   → Hover info / Completions

LIAISONS ENTRE COUCHES
════════════════════════════════════════════════════════════════════════════════

Composition (forte) :
─────────────────────
• CRDTEngine owns CRDTDocument
  → Si CRDTEngine mourir, documents disparaissent

• CollaborationEngine owns WebRTCCallManager, PermissionManager
  → Relation 1:1, lifecycle liés

• WorkspaceManager owns FileService
  → FileService dépend WorkspaceManager

• Room owns UserSession
  → Utilisateurs font partie d'une room

• SignalingWebSocketServer owns RoomManager
  → Gestion des rooms = responsibility serveur


Association (faible) :
──────────────────────
• CRDTDocument references CRDTIdentifier / CRDTElement / CRDTOperation
  → Utilise mais ne crée pas nécessairement

• CollaborationEngine uses CRDTEngine
  → Wrap pour collaboration, mais CRDTEngine peut exister seul

• DistributedIDEApp uses CollaborationEngine
  → Dépendance optionnelle (mode offline possible)

• LspBridgeSession references DocumentReplicaStore
  → Adaptateurpattern pour CRDT
