HOW THE STUB WORKS
════════════════════════════════════════════════════════════════════════════════

When LSP Bridge calls "jdtls":

1. Finds: ~/.local/bin/jdtls (symlink)
2. Points to: ~/.jdtls/bin/jdtls (stub script)
3. Stub checks: Is full jdtls installed in ~/.jdtls/plugins?
   
   ✅ YES → Runs full jdtls (Java LSP enabled)
   ❌ NO  → Exits with helpful message (graceful degradation)

This allows the IDE to start regardless, and users can upgrade
jdtls anytime by running BUILD_JDTLS_FROM_SOURCE.sh

IMPLEMENTATION DETAILS
════════════════════════════════════════════════════════════════════════════════

The stub wrapper code (~/. jdtls/bin/jdtls):

  #!/bin/bash
  JDTLS_HOME="${JDTLS_HOME:-...}"
  
  # Check if FULL jdtls installed
  if [ ! -d "$JDTLS_HOME/plugins" ]; then
      # Show helpful message about missing jdtls
      # Don't crash - just inform
      exit 1
  fi
  
  # Run full jdtls if available
  exec java -Dprocess=jdtls ...

This approach:
  1. Prevents "command not found" error
  2. Shows helpful instructions
  3. Can be upgraded transparently
  4. No code changes needed in IDE
